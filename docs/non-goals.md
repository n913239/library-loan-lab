# 6 條非目標

> 每一條都有理由,而且理由寫「範圍」不寫「難」。
> 沒有理由的禁令,三週後自己會想不起來為什麼,然後就會破例。
> 2026-09-17 隨規格簡化重寫:預約與排隊從功能變成第 1 條非目標。

| # | 不做 | 為什麼 |
|---|---|---|
| 1 | **預約與排隊** | 書被借走就是不能借。排隊、保留期限、逾時釋放是第二階段的題目,不是這一版的範圍 |
| 2 | **罰款 / 金流** | **只記逾期天數,不收錢**。金流是另一個系統 |
| 3 | 主動通知(到期提醒、Email / 推播) | 讀者自己 `GET /api/users/:id/borrows` 看;通知要靠外部服務與排程,不在範圍 |
| 4 | 多館 / 跨館借還 | 只做單一館,沒有館藏地與運送狀態 |
| 5 | 書目詮釋資料(ISBN、MARC、多作者、分類號) | 書只有 `id`、`title`、`status` |
| 6 | 身分驗證與權限 | request 帶 `userId` 就當合法;登入、token、館員角色都不在範圍 |

## 刻意保留的「醜」(要在文章裡承認)

這三項不是非目標(以後該做),是**現在刻意不做**:

- 沒有 rate limit
- 錯誤訊息不友善(只有 status code + 一句話)
- 逾期天數不排除假日與閉館日
