# 15 條非目標

> 每一條都有理由,而且理由寫「範圍」不寫「難」。
> 沒有理由的禁令,三週後自己會想不起來為什麼,然後就會破例。

| # | 不做 | 為什麼 |
|---|---|---|
| 1 | 條碼 / RFID 掃描 | 副本用文字編號;掃描端是另一個系統 |
| 2 | **罰款 / 金流** | **只記逾期天數,不收錢**。範圍與合規都爆炸 |
| 3 | 多館區 / 多租戶 | 只做單一館 |
| 4 | 書目匯入(ISBN 查詢、MARC) | 書目手動輸入,ISBN 是純文字欄位 |
| 5 | 推播 / Email 通知 | 改用清單:讀者自己 `GET /me/loans` 看到「保留中」 |
| 6 | 推薦系統 / 熱門排行 | — |
| 7 | 全文檢索 | 只做書名前綴 `?q=` |
| 8 | 管理後台 | 用 `wrangler d1 execute` 直接下 SQL |
| 9 | 封面圖片上傳(R2) | 純文字書目 |
| 10 | 國際化(i18n) | 只做繁中 |
| 11 | SSO / OAuth 第三方登入 | 自製 JWT 就是題目本身 |
| 12 | 離線 / 同步 | 純 API,沒有客戶端狀態 |
| 13 | 評論 / 評分 | — |
| 14 | 效能優化 | 除非免費額度真的爆(那才是素材) |
| 15 | 續借 | 到期就還,要再借重新排隊;續借會讓保留與排隊的競態多一倍 |

## 刻意保留的「醜」(要在文章裡承認)

這四項不是非目標(以後該做),是**現在刻意不做**:

- 沒有 rate limit
- 錯誤訊息不友善(只有 status code + 一句話)
- 沒有 log 聚合
- 逾期天數不排除假日與閉館日
