# 規格:圖書館借閱系統

> 這份講**要做什麼**。「做完」的定義寫成能判定的句子,不寫「使用者可以借書」這種沒有裁判資格的話。

## 一句話

圖書館借閱。每本書有若干副本,可借 14 天;全借出時可預約排隊,歸還後隊首保留 48 小時,逾時自動釋放給下一位。逾期只記錄天數,不收罰款。

## 每個 Feature 的「做完」定義

| Feature | 做完 = |
|---|---|
| 館藏與副本 | **只有館員能新增、下架副本**;測試證明讀者越權被拒 |
| **借閱 / 預約 / 保留 / 歸還** ⭐ | **併發測試通過(同一副本不雙借、保留只給隊首)**,且**逾期天數用 `due_at` 快照算**,且**保留逾時的三方競態行為被測試釘死** |
| 我的借閱與歷史 | 一次 `GET` 回傳目前借閱、排隊中、歷史三段,且 **SQL 查詢次數有算過** |

⭐ 那一列是整個專案的重心:一句話裡三個條件,而**沒有一個能靠讀 code 檢查**。

## API

### 認證
| Method | Path | 說明 |
|---|---|---|
| `POST` | `/auth/register` | 建立讀者 |
| `POST` | `/auth/login` | access token(短)+ refresh token(長) |
| `POST` | `/auth/logout` | 撤銷當前 refresh |

### 館藏
| Method | Path | 授權 | 說明 |
|---|---|---|---|
| `POST` | `/books` | 館員 | 書目:書名、作者、ISBN(純文字,不查外部 API) |
| `GET` | `/books` | 讀者 | 列表,可 `?q=` 書名前綴 |
| `GET` | `/books/:id` | 讀者 | 含副本數、可借數、排隊人數 |
| `POST` | `/books/:id/copies` | 館員 | 新增副本 |
| `DELETE` | `/copies/:id` | 館員 | 下架(只能下架 `available` 的) |

### 借閱與預約
| Method | Path | 授權 | 說明 |
|---|---|---|---|
| `POST` | `/books/:id/loans` | 讀者 | 借一個可借副本,借期 14 天 |
| `POST` | `/loans/:id/return` | 本人或館員 | 歸還;若有排隊者,建立保留給隊首 |
| `POST` | `/books/:id/reservations` | 讀者 | 排隊(全借出時) |
| `DELETE` | `/reservations/:id` | 僅本人 | 取消排隊 |
| `POST` | `/holds/:id/checkout` | 僅本人 | 把保留變成借閱 |

### 我的
| Method | Path | 授權 | 說明 |
|---|---|---|---|
| `GET` | `/me/loans` | 讀者 | 目前借閱、排隊中、歷史 |

合計 14 條。

## 狀態機

```
副本:  available → on_loan → available
          │                     ▲
          └─→ held ──(checkout)─┘  held ──(逾時 48h 或取消)──→ 還有人排隊?──是──→ held(下一位)
                                                                    └──否──→ available

借閱:  active → returned
          └─→ returned(逾期,記 overdue_days)

預約:  queued → held → fulfilled
          │       └─→ expired
          └─→ cancelled
```

## 必須被測試證明的規則

| 規則 | 測試 |
|---|---|
| 同一副本不能同時借給兩個人 | 併發 N 次借同一副本,只有一個成功 |
| 沒有可借副本時不能借 | 全借出後 `POST /loans` → 4xx |
| 保留只能給隊首 | 兩人排隊,歸還後只有第一位拿到 `held`;第二位 checkout → 4xx |
| 保留逾時後副本要能被別人借到 | 時間推 48h 後,隊首 checkout → 4xx;無人排隊時副本已 `available`,有人排隊時保留已順延給下一位 |
| 逾期天數用 `due_at` 快照 | 借出後改借期政策 → 歸還 → `overdue_days` 不受影響 |
| 只有館員能新增 / 下架副本 | 讀者 → 403 |
| 只能下架 `available` 的副本 | 對 `on_loan` 副本 `DELETE` → 4xx |
| `returned` 是終態 | 已歸還的借閱再 return → 4xx |
| 一人同一本書只能借一本、排一次 | 第二次 → 4xx |

> ⚠️ 第四條最容易漏:保留逾時的競態有**三方**(隊首、下一位、直接來借的人),
> 三方的行為都要釘死,而且**每一方的測試分開寫**。

## 規格層的決定(寫契約之前必須先有)

| # | 決定 | 怎麼做 | 為什麼 |
|---|---|---|---|
| 1 | **角色** | `readers.role` = `reader` \| `staff`;**只能用 SQL 改**,沒有 endpoint 能設角色 | 非目標 8 已經寫了「管理後台用 `wrangler d1 execute`」 |
| 2 | **借期** | 固定 14 天,存在 `loan_policies` 表(一列);借出時把算好的 `due_at` 寫進 `loans` | 硬規則 5:歸還時用快照,不重算 |
| 3 | **保留時間** | 固定 48 小時,**跟借期一起存在 `loan_policies` 那一列(`hold_hours`)**;建立保留時把算好的 `expires_at` 寫進保留紀錄,之後只看快照 | 同上。2026-09-17 補:原本只寫「固定 48 小時」沒說存哪,是 Day 7 實驗裡 AI 第二輪問出來的 |
| 4 | **一人幾本** | 同一本書一人**同時最多一個關係**:借閱中、排隊中、保留中三者擇一;**已借走這本書的人不能再排同一本**(409);不同書不限 | 讓「同一人重複送出」不污染併發測試。2026-09-17 補:原本只寫「一本借閱、一個排隊」,沒說能不能同時,是 Day 7 實驗裡 AI 第二輪問出來的;順便堵掉非目標 15 的續借後門(還書→自己是隊首→再借) |
| 5 | **逾時釋放** | 保留過期或被取消後,**順延給下一位隊首**;沒有人排隊才變 `available`(行為要求;用什麼機制屬於 schema) | 這是行為契約,不是實作方式。2026-09-16 補:原本一句話寫「給下一位」、狀態機畫「→ available」,兩處對不起來,是 Day 7 實驗裡 AI 在沒讀到這份規格的情況下問出來的 |
