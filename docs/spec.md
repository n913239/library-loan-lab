# 規格:圖書館借閱系統(最簡版)

> 這份講**要做什麼**。「做完」的定義寫成能判定的句子,不寫「使用者可以借書」這種沒有裁判資格的話。
> 2026-09-17 從「副本 + 預約 + 保留」版簡化成這版(舊版在 git 歷史 `4cf64d3` 之前):一本書就是一冊,借走了別人就不能借,沒有排隊。

## 一句話

圖書館借閱。每本書就是一本實體書,讀者借走 14 天,還了別人才能借。逾期只記錄天數,不收罰款。

## 每個 Feature 的「做完」定義

| Feature | 做完 = |
|---|---|
| 查書 | `GET` 回書名與狀態(`available` / `on_loan`),且**狀態跟借閱紀錄一致**:有未歸還紀錄 ⇔ `on_loan`,測試證明 |
| **借書** ⭐ | **併發測試通過(N 個人同時借同一本,恰好一人成功、其餘被拒)**,且 **`due_at` 是借出當下算好的快照**(借出後改借期政策,既有紀錄的 `due_at` 不變,測試證明) |
| 還書 | 只能還自己未歸還的紀錄;還完**立刻**可借(測試:還完馬上再借得到);已歸還再還 → 4xx;`overdue_days` 用 `due_at` 快照算 |
| 我的借閱 | 一次 `GET` 回未歸還、歷史兩段(各帶 `overdueDays`,決定 6),且 **SQL 查詢次數有算過** |

⭐ 那一列是整個練習的重心:兩個條件,**沒有一個能靠讀 code 檢查**。

## API

| Method | Path | 說明 |
|---|---|---|
| `GET` | `/api/books/:id` | 書名、狀態(`available` / `on_loan`) |
| `POST` | `/api/borrow` | body `{ userId, bookId }`;借期 14 天,回借閱紀錄(含 `due_at`) |
| `POST` | `/api/return` | body `{ userId, bookId }`;找該讀者對該書未歸還的紀錄,押上 `returned_at` 與 `overdue_days` |
| `GET` | `/api/users/:id/borrows` | 未歸還 + 歷史 |

合計 4 條。身分:request 帶 `userId`,**不驗**(非目標 6)。

## 狀態機

```
書:      available → on_loan → available
借閱紀錄: active → returned(終態;逾期只是 overdue_days > 0,不是另一個狀態)
```

## 必須被測試證明的規則

| 規則 | 測試 |
|---|---|
| 同一本書不能同時借給兩個人 | 併發 N 次借同一本,只有一個成功 |
| 書在 `on_loan` 時不能借 | 借走後再 `POST /api/borrow` → 4xx |
| 一人同一本書只能有一筆未歸還 | 同一人重複借同一本 → 4xx |
| 還完立刻可借 | `return` 之後緊接 `borrow` → 201 |
| `returned` 是終態 | 已歸還的再 `return` → 4xx |
| 只能還自己的 | 別人的紀錄 `return` → 4xx |
| 逾期天數用 `due_at` 快照 | 借出後改借期政策 → 歸還 → `overdue_days` 不受影響 |
| 時間是參數 | domain 函式給不同的 `now` 得到不同結果,而且不讀時鐘 |
| 狀態轉移只認白名單 | 非法轉移(`on_loan` 再 `borrow`、`available` 就 `return`)→ `IllegalTransitionError`;未知狀態/事件(非字串、大小寫不符、`reserved` 之類)→ `TypeError` |

## 規格層的決定(寫契約之前必須先有)

| # | 決定 | 怎麼做 | 為什麼 |
|---|---|---|---|
| 1 | **一書一冊** | `books` 一列就是一本實體書,沒有副本表 | 最簡版;多副本是第二階段 |
| 2 | **借期** | 固定 14 天,存在 `loan_policies` 表(一列);借出時把算好的 `due_at` 寫進 `borrow_records` | 硬規則 5:歸還時用快照,不重算 |
| 3 | **逾期天數** | `max(0, floor((now − due_at) / 86400 秒))`,純 UTC 秒差,不看日曆日 | 硬規則 4;未滿一天不算,逾期只記錄不收錢,寬鬆沒有成本 |
| 4 | **一人幾本** | 同一本書一人只能一筆未歸還;不同書不限 | 讓「同一人重複送出」不污染併發測試 |
| 5 | **身分** | `users` 表只有 `id`、`name`;request 帶 `userId`,不驗、不分角色 | 非目標 6;`userId` 查不到才 4xx |
| 6 | **列表帶不帶逾期天數** | `GET /api/users/:id/borrows` 兩段都帶 `overdueDays`:未歸還那段用 request 當下的 `now` 現算,歷史那段讀還書時押進去的 `overdue_days` | 2026-09-17 補:Plan Mode 第二輪問出來的,規格原本沒寫;「歷史讀存的」是 /grill-me 追問後定的 —— 存的欄位若只寫不讀就是多一份真相 |
