# `books.status` 是唯一真相來源,即使它對借閱紀錄是冗餘的

「這本書借出中」與「這本書有一筆未歸還紀錄」是同一件事的兩種說法,
但我們仍然把狀態存成 `books` 上的一個欄位,而不是從 `borrow_records` 推導。
理由是硬規則 3:併發判斷必須寫在 SQL 的 `WHERE` 裡並檢查 `changes` ——
只有當狀態是一個**可以被條件式 UPDATE 的欄位**時,這條規則才有地方落腳。
反過來,若狀態純由紀錄推導,驗收條件「查書的狀態跟借閱紀錄一致」會退化成恆真的廢話,測不到任何東西。

## Consequences

- 我們**主動接受了冗餘**,代價是得自己維持不變量。兩道防線:
  借書與還書的兩句寫入放進同一個 `batch()`(原子),
  加上 `borrow_records(book_id) WHERE returned_at IS NULL` 的 partial unique index(兜底)。
- 那個 index 一旦被觸發,代表條件式 `WHERE` 守衛失效,**那是 bug 不是使用者做錯事**:
  讓它 500 並大聲記錄,不要包成 409。用第二道防線去掩蓋第一道防線的失效,正好相反。
- 借書時「書不存在」與「書被借走」在守衛式寫入下**同形**(`changes` 都是 0)。
  要分辨只能在失敗路徑多查一次 —— 成功路徑零成本,因為永遠走不到那裡。
- 狀態字面值(`'available'` / `'on_loan'`)只能出現在 `src/domain/book-state.js`,
  SQL 一律綁參數。否則硬規則 2 的靜態檢查會把正確的 repository 程式碼判成違規。
